## 1. 核心提示词 (Prompt)
"我已经把 bvids.txt 替换成真实视频号，请帮我跑通 bilichat-ingest 全链路：爬取 → 落 JSONL → 推 /api/chat/upload → MQ → 双引擎 → 落库 → 大屏，并在前端把每个面板都过一遍发现问题就修。"

## 已完成
1. **环境绕过**：venv 内 pip 走 PyPI/清华源均 `SSL EOF`，定位到 LibreSSL 与代理兼容性问题；改用系统 `/usr/bin/python3 3.9`（自带 `requests 2.32.4`/`certifi`）直接跑脚本，跳过依赖安装。
2. **B 站接口变更适配**：
   - `/x/v2/reply` 的 `ps` 上限 30 → 20，否则全部 `code=-400 ps out of bounds`。在 `bilichat-ingest/ingest_comments.py` 把默认值改成 20。
   - 未登录访客每个视频仅返回 3 条「精选评论」第二页就空。要求用户从浏览器抓 `SESSDATA` Cookie 并通过 `--cookie` 传入，触底后每页恢复 20 条。
3. **完成 12 000 条真实评论灌库**：
   - 14 个 BV，按热度 sort=2 抓取累计 12 000 条根评论。
   - 50 QPS / 16 线程推送 `/api/chat/upload`，全部 200，无 429。
   - 库内最终 `total=14547`、`BLOCK=923`、`REVIEW=378`、阻断率 6.34%（含历史数据）。
4. **覆盖前端 4 个面板**：压测入口 / 实时大屏 / 审核后台 / 规则控制台，对每个面板手动操作并验证大屏指标响应。
5. **发现严重 BUG**：审核后台「封禁 / 解除 / 批量封禁 / 批量解除」点击后无任何反馈。经定位为雪花 ID 19 位 → JS `Number` 安全位 16 位 → 前端拿到的 `id` 末两位被四舍五入丢失 → 后端按错 ID 查 404 → 前端缺 `else` 分支静默。已联动 P5 / P8 修复（见各角色日志）。

## 价值
- 真实评论替代造数据，模型召回 / 阻断率不再依赖固定话术池，置信度大幅提升。
- 暴露了一个潜伏多时的「Long → JSON → JS Number」精度丢失链路问题，避免上线后用户操作完全失效。
- 沉淀出"如何用真实流量做端到端回归"的标准操作路径，可在后续模型版本迭代中复用。
